# Auren Block Standard

This directory contains versioned catalog source. A block is copied source, not
a pnpm workspace package. Every block must follow this standard before it can be
added to the catalog.

## Canonical Tree

Use the exact taxonomy identifiers in the path. The initial category roots are
`marketing`, `application-ui`, `ecommerce`, and `authentication`.

```text
blocks/
└── <category>/
    └── <type>/
        └── <type>-NNN/
            ├── component.tsx
            ├── registry.json
            ├── components/       # optional .tsx payloads
            ├── utilities/        # optional .ts or .tsx payloads
            ├── styles/            # optional .css payloads
            └── assets/            # optional local assets
```

`<category>` and `<type>` are official taxonomy identifiers, not display names
or aliases. `<type>-NNN` uses a zero-padded number from `001` through `999`.
The complete catalog must not reuse an id, even in another category or type.
Allocate the next available id deliberately and check the whole `blocks/` tree
before opening a change.

Each block root contains exactly these required root files:

- `component.tsx` is the block entry component.
- `registry.json` is the only source manifest.

Additional source files must be inside one of the four designated payload
directories. Do not commit a fake or placeholder block merely to document the
layout; verifier tests create temporary fixtures instead.

## Source Manifest

`registry.json` must be accepted unchanged by the public
`catalogElementSchema` from `@auren/schemas/catalog`. The schema is strict and
requires the twelve catalog fields: `id`, `name`, `description`, `category`,
`type`, `styles`, `industries`, `features`, `frameworks`, `dependencies`,
`files`, and `metadata`.

Identity fields must repeat the path exactly:

```json
{
  "id": "hero-001",
  "name": "Product launch hero",
  "description": "A responsive product launch hero.",
  "category": "marketing",
  "type": "hero",
  "styles": ["minimal"],
  "industries": ["saas"],
  "features": ["mobile-first", "responsive"],
  "frameworks": ["react"],
  "dependencies": [],
  "files": [
    { "path": "component.tsx", "kind": "component" }
  ],
  "metadata": {}
}
```

The source manifest is not an installation manifest. Every `files` descriptor
uses a safe relative POSIX `path` and a supported `kind`. List every regular
payload file exactly once, except `registry.json`, which must never appear in
`files`. The root `component.tsx` descriptor is mandatory and must use kind
`component`. Source descriptors must omit both `target` and `content`:

- `target` belongs to the later installation policy.
- `content` is generated by the later Registry Build step.

Do not add a second block manifest, handwritten schema, or unlisted support
file. `metadata` remains JSON-safe and the taxonomy values must be the exact
official values; nothing is trimmed, recased, aliased, or silently defaulted.

## Payload Inventory

The directory determines the file kind. Do not make the verifier guess.

| Location | Allowed regular files | Manifest kind |
| --- | --- | --- |
| `component.tsx` at the block root | exactly the entry file | `component` |
| `components/` | `.tsx` files at any nested depth | `component` |
| `utilities/` | `.ts` or `.tsx` files at any nested depth | `utility` |
| `styles/` | `.css` files at any nested depth | `style` |
| `assets/` | any regular file with a valid asset filename | `asset` |

Source files outside these locations, unsupported extensions, duplicate
descriptors, undeclared files, descriptors for missing files, and kind/location
mismatches are invalid. Descriptor paths must not be absolute, use backslashes,
contain empty, `.` or `..` segments, or use a Windows drive prefix.

Asset directories below `assets/` use lowercase kebab-case segments. Asset
filenames use one lowercase kebab-case stem, one dot, and one lowercase
alphanumeric extension, for example `assets/product-preview.webp`. Required
assets live in the block and are referenced with relative paths; the default
presentation must not depend on a hotlinked image or other remote asset.

Styles are optional. Tailwind CSS v4 is the default styling mechanism. A
declared CSS file must be scoped to the block and must not reset or mutate
unrelated application-wide styles.

## Frameworks, Imports, and Dependencies

Blocks use React, TypeScript, and Tailwind CSS v4 as the initial baseline.
React baseline imports are exactly these package roots and subpaths:

- `react` and `react/*`
- `react-dom` and `react-dom/*`

This exemption includes type-only imports. Every other bare package import,
including a type-only import, needs exactly one matching `package` descriptor in
`dependencies`. Match the package root, not the imported subpath:

```json
{
  "kind": "package",
  "name": "motion",
  "version": "^12.0.0"
}
```

The descriptor above covers `motion/react`; an import such as
`@scope/pkg/subpath` requires a descriptor for `@scope/pkg`. Do not declare
optional or unused packages. Simple blocks should remain dependency-light;
shadcn/ui is an optional later integration, not a baseline dependency.

Relative imports, including stylesheet imports, must stay inside the containing
block. Do not import from `apps/`, `packages/`, another block's source tree, or
private workspace modules. Installed block source must not retain a runtime
import from any `@auren/*` package. If a block requires another Auren element,
declare exactly one matching `auren` descriptor:

```json
{
  "kind": "auren",
  "id": "button-001"
}
```

A block may require a canonical shadcn/ui source component without copying its
source into the block:

```json
{
  "kind": "shadcn",
  "name": "button"
}
```

Every such requirement must be imported through the canonical module prefix
`@/components/ui/<name>`. Auren adapts that prefix to the consumer's
`components.json.aliases.ui` during installation. Do not use a registry URL,
namespaced/custom registry identifier, arbitrary consumer filesystem path, or
a block-local `components/ui/` copy. Shadcn descriptors contain only a safe
lowercase kebab-case component name; they are source requirements, not npm
packages, and have no version field.

Package, Auren, and shadcn dependency descriptors belong in the manifest's
`dependencies` array. Each descriptor must describe a real requirement; it is
not a way to reserve a package or silence an import review. A canonical
shadcn import without its matching descriptor, or an unused shadcn descriptor,
is invalid.

A block directory and every descendant must not contain `package.json` or any
other workspace manifest. Blocks remain outside pnpm workspace globs and are
never independently installed or published as packages.

## Responsive and Accessible UI

Every manifest must include both `mobile-first` and `responsive` in `features`.
Those labels are behavior requirements, not decorative tags:

- Author the base layout for a 320 CSS-pixel viewport first.
- Keep representative content readable and usable without block-caused
  horizontal overflow at 320 CSS pixels.
- Adapt layout, spacing, and readable content through desktop widths, including
  a representative 1280 CSS-pixel viewport.

Dark mode is optional. Declare `dark-mode` only when every visible surface,
text color, border, control, focus state, hover state, and disabled state stays
legible inside Tailwind's class-based dark-mode context. Remove the feature if
the implementation does not satisfy that claim.

Declare `animated` only when the block contains intentional motion. Do not use
the feature as a promise for incidental browser behavior. All non-essential
motion must unconditionally honor the user's reduced-motion preference, using
the appropriate CSS or runtime behavior. A dark-mode or animation claim must
match the rendered implementation in every visible state.

Use native semantic HTML before custom ARIA behavior. Within the documented
composition context:

- Keep a logical heading hierarchy.
- Give every control an accessible name and use native buttons, links, and form
  controls where they fit.
- Make every interaction keyboard-operable with a logical order and visible
  focus indicator.
- Do not communicate meaning with color alone.
- Give informative images meaningful alternative text and mark decorative
  images as decorative.
- Associate form controls with visible labels and expose validation meaning
  when a form exists.
- Keep focus, hover, active, disabled, and error states understandable in all
  supported themes.

## Verification Boundaries

`pnpm check` builds `@auren/schemas`, verifies the dependency-free workspace
topology, and then scans the complete `blocks/` tree. It mechanically enforces:

- The four pinned category roots and their exclusion from the pnpm workspace.
- Required block depth, root files, exact path/manifest identity, id syntax, and
  catalog-wide id uniqueness.
- Public `catalogElementSchema` validity and the mandatory `mobile-first` and
  `responsive` features.
- Explicit canonical shadcn descriptors for shadcn imports, with no copied
  shadcn source or custom registry identifiers.
- Safe, complete, one-to-one file inventories and designated file kinds.
- Asset path grammar, unexpected source entries, and absence of nested package
  manifests.

`pnpm test` builds Schemas, runs the temporary-fixture Node verifier tests, and
then runs the existing package tests. Both commands consume the public package
entrypoint; neither imports private schema source files. `pnpm registry:build`
performs the same source preflight and materializes the ignored `dist/registry/`
catalog for distribution; it never writes inside `blocks/`.

The following remain normative author and review obligations until their
dedicated automation exists:

- Import resolution and proof that every external import has a matching
  dependency descriptor.
- Rendered responsive behavior at representative viewport widths.
- Complete rendered dark-mode and interaction-state coverage.
- Visual regression and quality review.
- Automated accessibility validation, including keyboard and assistive
  technology checks.

These later checks belong to Quality Validation, Visual Testing, and
Accessibility Validation rather than to token matching in the structural
verifier. A passing `pnpm check` proves source-tree consistency, not the full
quality of a rendered block.
